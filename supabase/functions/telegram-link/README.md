# telegram-link — código de vínculo da conta existente

Endpoint POST com **verify_jwt=true**. Usa `userIdFromAuthorization` da chat, validando JWT localmente (assinatura, expiração, issuer, audience); a checagem do gateway permanece obrigatória. Sem JWT válido: 401 antes de ler corpo ou abrir DB. Nenhum user_id recebido no corpo é usado.

Emissão: 20 caracteres de alfabeto com 32 símbolos sem 0/1/I/O, formatados em quatro grupos de cinco (100 bits aleatórios via Web Crypto). O código aparece somente na resposta `no-store` para o dono autenticado. O banco recebe apenas HMAC-SHA-256 do código normalizado, com pepper obrigatório de ao menos 32 caracteres. Pepper ausente/curto fecha o endpoint com 503 antes de DB. Vigência de dez minutos, uso único e emissão no máximo a cada 30 segundos por conta. Não há código em URL de deep link, log ou armazenamento persistente da página.

O usuário abre https://aion.hernandesnogueira.com.br/vincular.html, entra pelo mesmo cliente de login do site, gera o código e envia `/start <código>` ao **@aion_codigosdopoder_bot**. Não há criação de usuário Auth pelo bot. O código pode ser digitado sem hífens e em minúsculas. Reemissão invalida o código anterior daquela conta. O logout explícito espera a emissão em voo. Timeout, falha de rede ou HTTP 5xx dessa emissão não confirmam a saída: a conta continua conectada para tentar de novo. Sem token de acesso não há `{revogado:true}`: se a sessão ainda está visível, a página recusa o sucesso; se não há sessão, só limpa a tela. Com token, envia `{revogar:true}` e só conclui quando o HTTP está ok e o corpo tem `{revogado:true}`. A RPC, no mesmo advisory lock da emissão, grava `revoked_at` do usuário e apaga códigos ainda não usados. `telegram_issue_code` só insere se o `iat` daquele JWT for posterior ao marco. O `iat` sai do JWT já autenticado; `user_id` e `iat` do corpo são ignorados. `pagehide` só descarta o código na tela e não revoga.

A RPC de consumo serializa emissão/rebind/desvínculo e, numa transação, marca o código usado, libera os dois vínculos anteriores e insere a nova correspondência um a um. Invalida provas de sessão afetadas, sem apagar hashes que impedem replay. `/desvincular` só age no telegram_id autenticado pelo webhook privado.

O acesso é feito com `ATLAS_CHAT_DB_URL` / chat_fn e RPCs fechadas da migração 013. Nunca service_role. Tabelas privadas com RLS, sem grants aos clientes. A função `chat` e seu JWT ficam intactos.

Nomes de ambiente usados diretamente ou pela autenticação: `TELEGRAM_LINK_PEPPER`, `ATLAS_CHAT_DB_URL`, `JWT_SECRET`, `SUPABASE_JWT_SECRET`, `SUPABASE_URL`. Veja os testes `handler_test.ts` e o runner `../_shared/telegram_node_test.mjs`. Toda autenticação e código nas suítes são sintéticos; nenhuma chamada real a Auth, Telegram ou inferência.
